# Deployment and local development

The live application runs on Sites with a Cloudflare Worker and D1 binding `DB`. No R2 binding is used. This public repository includes a hosting configuration template without the production project identifier. Create your own project and database; never copy someone else's hosting identity.

## Local development

Use Node.js 22.13+ and pnpm 11.25.0. Install from the lockfile, generate the public source index and build as shown in the README. `pnpm dev` uses the portable execution profile in a clean clone.

The development-only sign-in adapter is restricted to loopback. It uses `seedy@sites.test`; set `ADMIN_EMAIL=seedy@sites.test` in a gitignored `.dev.vars` to test the owner dashboard locally. Production authentication must not use this adapter.

To prepare a local database, run the development server once so Wrangler creates local state, then apply the checked-in migration with the project's Wrangler installation:

```sh
node node_modules/wrangler/bin/wrangler.js d1 execute site-creator-d1 --local --file drizzle/0000_serious_tyrannus.sql
```

Use the config generated by your local build or development server if Wrangler requests it. The migration targets your local database only. The test suite applies the schema itself in an isolated database.

## Production authentication boundary

The application trusts `oai-authenticated-user-*` identity headers supplied by the Sites dispatch layer and checks `ADMIN_EMAIL` on the server. On a different host, an equivalent trusted authentication gateway must remove visitor-supplied identity headers and inject verified identity, or the admin authentication must be replaced. Do not expose the unchanged owner routes directly on an untrusted origin.

## Runtime values

- `ADMIN_EMAIL`: private owner allowlist, stored as a hosting secret.
- `DB`: a D1 binding provisioned for your own deployment.
- `MCP_REGISTRY_PROOF`: optional public ownership proof for your domain.
- `INDEXNOW_KEY`: optional ownership verification value, configured in hosting.

No model API key is needed. Never commit private keys, agent bearer tokens, environment files or database exports.

## Publication

On Sites, register your own project, retain its returned identifier in your private deployment checkout, build through the supported Sites workflow, and apply pending hosted migrations when publishing. Other hosting providers need their own Worker, D1 and authentication configuration. The public `lib/discovery.ts` URLs and MCP Registry namespace describe this project's live service; change them before announcing an independent deployment.
